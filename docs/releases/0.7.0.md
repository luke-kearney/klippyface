> [!TIP]
> **Setting up a new display no longer needs any addresses.** Leave the server address blank in the setup portal: the display finds the server on your network by itself, and shows up on the **Nodes** page as pending. Click **Accept** and it gets its faces.

> [!WARNING]
> **The two ESP32-S3 firmware builds are still untested on hardware**, as are their ST7789 / GC9A01 drivers. Please report what you see (serial log + photo) on [#21](https://github.com/luke-kearney/klippyface/issues/21) (LCD-1.69) or [#29](https://github.com/luke-kearney/klippyface/issues/29) (LCD-1.28). The classic ESP32 build is tested.

## Which file do I need?

| File | Device | Status |
|------|--------|--------|
| `klippyface-firmware-0.7.0-esp32dev.bin` / `-full.bin` | Classic ESP32 DevKit (ESP-WROOM-32) with an SH1106 OLED or HX8347D parallel TFT | ✅ Tested |
| `klippyface-firmware-0.7.0-esp32s3-ws-lcd169.bin` / `-full.bin` | Waveshare ESP32-S3-Touch-LCD-1.69 (ESP32-S3R8, ST7789V2 240×280) | ⚠️ Untested |
| `klippyface-firmware-0.7.0-esp32s3-ws-lcd128.bin` / `-full.bin` | Waveshare ESP32-S3-LCD-1.28 (ESP32-S3R2, GC9A01 240×240 round) | ⚠️ Untested |
| `docker-compose.yml` | Companion server in Docker, Linux x86-64 or ARM64: `docker compose up -d` in its folder | ✅ Tested on x86-64 |
| `klippyface-server-0.7.0-linux-x64.tar.gz` | Companion server + Web UI, x86-64 Linux | ✅ Tested |
| `klippyface-server-0.7.0-linux-arm64.tar.gz` | Companion server + Web UI, 64-bit ARM Linux (e.g. Raspberry Pi) | Same code as x64; ARM build not run by us |
| `klippyface-server-0.7.0-win-x64.zip` | Companion server + Web UI, Windows x64 | New; not run by us |

- **`-full.bin`** is for a blank or erased board: flash it at `0x0` with `esptool write-flash 0x0 <file>` or a browser flasher such as [ESPTool](https://esptool.spacehuhn.com/) (Chrome or Edge)
- **`.bin`** (no `-full`) is the app only, for updating a board that already runs Klippyface
- A firmware build only works on the device it's named for

## Highlights

- **Displays find the server themselves** ([#46](https://github.com/luke-kearney/klippyface/issues/46)): the server advertises itself over mDNS (`_klippyface._tcp`). A display with no server address looks for it, and a display whose server has been unreachable for 30 s looks again, so a server that gets a new IP is found without resetting anything. Works on one network; across VLANs or guest WiFi, type the address in as before
- **New displays register themselves** ([#43](https://github.com/luke-kearney/klippyface/issues/43)): an unknown display appears on the **Nodes** page as pending instead of being turned away, so there's no MAC address to copy out of the log. Accept it (the Waveshare boards get their display set up automatically) or reject it. **Clear pending** removes the lot
- **Docker** ([#45](https://github.com/luke-kearney/klippyface/issues/45), [#47](https://github.com/luke-kearney/klippyface/issues/47)): download `docker-compose.yml` and run `docker compose up -d`. The image (`ghcr.io/luke-kearney/klippyface-server`, x86-64 and ARM64) keeps its data in a volume and uses host networking so displays can discover it. On Docker Desktop (Mac/Windows) see the comments in the file
- **Windows server** ([#44](https://github.com/luke-kearney/klippyface/issues/44)): `klippyface-server-0.7.0-win-x64.zip`. Allow it on private networks when Windows Firewall asks
- **Start the server from anywhere:** the tarball and zip find their Web UI and database next to their own files, whichever folder you start them from. `KLIPPYFACE_DATA_DIR` moves the database
- **Setup portal:** the server address is optional ("Blank = find automatically")

## Upgrading

1. **Server first.** The database migrates on start; existing displays are kept as accepted. If you start the server from inside its folder, as before, nothing else changes
   - If you used to start it from a *different* folder, its database was in that folder. Move `klippyface.db` next to `Klippyface.Server`, or set `KLIPPYFACE_DATA_DIR` to the folder it's in
   - **Moving to Docker:** run `docker compose up -d` once and then `docker compose down`, so the volume exists. Then, from the folder holding your old `klippyface.db` (stop the old server first):
     ```bash
     docker run --rm -v klippyface_klippyface-data:/data -v "$PWD":/src alpine \
       sh -c 'cp /src/klippyface.db /data/ && rm -f /data/klippyface.db-wal /data/klippyface.db-shm && chown 1654:1654 /data/klippyface.db'
     docker compose up -d
     ```
     Or start fresh and accept your displays again
2. **Then the displays.** Flash the `.bin` for the board; settings are kept. Displays with a saved address keep using it, and fall back to discovery if it stops answering. To switch one to discovery, hold BOOT for 3 seconds and leave the address blank in the setup portal

0.6.0 firmware keeps working with a 0.7.0 server (it just can't discover it). A 0.7.0 display with a blank address needs a 0.7.0 server to find.

## Not tested on hardware

- The ESP32-S3 builds (see above)
- The ARM64 server build and Docker image on a real ARM board
- The Windows server, including discovery next to Windows' own mDNS service
- Docker Desktop
- More than one Klippyface server on the same network (a display takes the first one that answers)
