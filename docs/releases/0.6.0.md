> [!IMPORTANT]
> **Update the server before the displays.** In 0.6.0 the server connects to Moonraker and passes printer data on to the displays, which no longer connect to Moonraker themselves. A 0.6.0 display gets no printer data from a 0.5.0 server. After updating the server, enter Moonraker's address on its new **Printer** page.

> [!WARNING]
> **The two ESP32-S3 firmware builds are still untested on hardware**, as are their ST7789 / GC9A01 drivers. Please report what you see (serial log + photo) on [#21](https://github.com/luke-kearney/klippyface/issues/21) (LCD-1.69) or [#29](https://github.com/luke-kearney/klippyface/issues/29) (LCD-1.28). The classic ESP32 build is tested.

## Which file do I need?

| File | Device | Status |
|------|--------|--------|
| `klippyface-firmware-0.6.0-esp32dev.bin` / `-full.bin` | Classic ESP32 DevKit (ESP-WROOM-32) with an SH1106 OLED or HX8347D parallel TFT | ✅ Tested |
| `klippyface-firmware-0.6.0-esp32s3-ws-lcd169.bin` / `-full.bin` | Waveshare ESP32-S3-Touch-LCD-1.69 (ESP32-S3R8, ST7789V2 240×280) | ⚠️ Untested |
| `klippyface-firmware-0.6.0-esp32s3-ws-lcd128.bin` / `-full.bin` | Waveshare ESP32-S3-LCD-1.28 (ESP32-S3R2, GC9A01 240×240 round) | ⚠️ Untested |
| `klippyface-server-0.6.0-linux-arm64.tar.gz` | Companion server + Web UI, 64-bit ARM Linux (e.g. Raspberry Pi) | Same code as x64; ARM build not run by us |
| `klippyface-server-0.6.0-linux-x64.tar.gz` | Companion server + Web UI, x86-64 Linux | ✅ Tested |

- **`-full.bin`** is for a blank or erased board: flash it at `0x0` with `esptool write-flash 0x0 <file>` or a browser flasher such as [ESPTool](https://esptool.spacehuhn.com/) (Chrome or Edge)
- **`.bin`** (no `-full`) is the app only, for updating a board that already runs Klippyface
- A firmware build only works on the device it's named for

## Highlights

- **The server relays Moonraker** ([#34](https://github.com/luke-kearney/klippyface/issues/34)): one Moonraker connection on the server, and each display gets only the values its faces use. `RESPOND display:` lines are routed by `node=`
- **Printer states for faces** ([#36](https://github.com/luke-kearney/klippyface/issues/36)): idle, busy, heating, printing, paused, complete, cancelled and error, worked out by the server. Klipper shutdowns show as error instead of Moonraker offline. New starter faces for heating, busy and cancelled
  - A preheat with no print running shows **heating** until the heaters reach their targets
  - A finished print's complete/cancelled face is dismissed when the motors are turned off, Klipper's idle timeout fires or the file is cleared, and it stays dismissed when you home or move afterwards
- **Screen sleep follows the printer** ([#38](https://github.com/luke-kearney/klippyface/issues/38)): displays stay on while printing, paused, heating, busy or in error, and sleep after a timeout once the printer rests. Set it per node under **Screen sleep** on the node page (1 minute to 1 hour, or Never; default 5 minutes)
- **Redesigned setup portal**: labelled fields, a network list with signal strength that fills in on its own, and reliable WiFi scanning (it used to need several taps). Phones open it automatically when they join `Klippyface-Setup`
- **The degree sign shows properly** (`215°C`), as do arrows, `±`, `µ`, `²` and common accented letters; other characters show as `?`, the same in the Web UI preview
- **Fake Moonraker** (`tools/FakeMoonraker`) for developing without a printer ([#35](https://github.com/luke-kearney/klippyface/issues/35)), and a server test suite
- **Fixes:** progress now comes from `display_status` (it always showed 0%), partial Moonraker updates no longer zero missing values, single-frame faces redraw when a value changes

## Upgrading

1. **Server first.** Database migrations run automatically on start (new columns only). Then open the **Printer** page and enter Moonraker's address (usually the Pi's IP, port 7125)
2. **Then the displays.** Flash the `.bin` for the board. Displays set up on 0.5.0 keep their settings:
   - if you entered a companion server address, they connect to it as before
   - if you left it empty, they use their saved Moonraker address as the server address, which works when the server runs on the same machine as Moonraker. Otherwise hold BOOT for 3 seconds to reset the display, and enter the server's address in the setup portal
3. Screen sleep defaults to 5 minutes on every node, as before; change it on each node's page

Older (0.5.0) firmware keeps working with a 0.6.0 server, but without state-aware screen sleep, the per-node timeout or the glyph fix.

- The degree sign and other glyphs on a real panel
